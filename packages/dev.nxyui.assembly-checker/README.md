# Assembly Checker (조립 점검기)

[← NXYUI Avatar Tools](../../README.md)

의상과 기믹을 조립한 뒤, VRChat에 올려 보기 전에 문제를 한 화면에 모아 보여 주는 Unity 에디터 도구입니다.
아바타의 복제본을 NDMF로 빌드해서, Modular Avatar가 합치고 바꾼 뒤의 모습 그대로 점검합니다. 씬의 아바타는 바뀌지 않습니다.

빌드할 때 아무 데서도 쓰지 않는 Expression Parameter를 지워 동기화 비트를 줄이는 기능도 들어 있습니다.

## 요구 사항

- Unity 2022.3, VRChat SDK - Avatars 3.10.6 이상
- NDMF 1.14.8 이상, Modular Avatar 1.18.7 이상

## 시작하기

1. Edit Mode에서 상단 메뉴 **NXYUI › Assembly Checker**를 엽니다.
2. ‘아바타’ 칸에 씬의 아바타를 넣습니다. Hierarchy에서 아바타를 고르면 자동으로 들어갑니다.
3. **점검하기**를 누릅니다. 복제본을 빌드하는 데 몇 초 걸립니다.
4. 탭(점검 · 텍스처 · 파라미터)에서 결과를 봅니다. 왼쪽 목록에서 항목을 고르면 오른쪽에 자세한 내용이 나옵니다.

의상을 고친 뒤에는 다시 **점검하기**를 눌러야 결과가 바뀝니다.

## 점검 탭

| 점검 | 찾는 것 | 고치는 방법 |
|---|---|---|
| 의상 아마추어 | 아바타 아마추어 밖의 Hips·Spine·Chest 본을 쓰는 의상. 의상이 몸을 따라 움직이지 않습니다. | 의상을 우클릭해 Modular Avatar › Setup Outfit |
| PhysBone 중복 | PhysBone 두 개가 같은 본을 움직이는 경우. 의상과 아바타에 같은 머리카락·꼬리 PhysBone이 있을 때 생깁니다. | 하나를 지우거나 한쪽의 Ignore Transforms에 넣기 |
| Anchor Override | 바디와 다른 Anchor Override를 쓰는 렌더러. 같은 자리에서도 밝기가 달라 보입니다. | 아바타 루트에 MA Mesh Settings |
| Bounds | 메시보다 작은 Bounds(화면 가장자리에서 일부가 사라짐), 비어 있는 Root Bone | Bounds를 넓히거나 MA Mesh Settings |
| 바디 줄이기 | 의상을 입었는데 바디의 줄이기 쉐이프키(Shrink, 縮, Hide 등)가 모두 0인 경우 (참고) | 맞는 키를 올리기. MA Shape Changer를 쓰면 의상을 끌 때 같이 돌아갑니다 |
| 꺼진 오브젝트 | 꺼져 있고 어떤 애니메이션도 켜지 않는데 업로드되는 오브젝트. 변환하고 남은 원본 의상이 흔합니다. | EditorOnly 태그를 붙이거나 지우기 |

- **경고**는 VRChat에서 보이는 문제이고, **참고**는 상황에 따라 괜찮을 수 있는 것입니다.
- 항목을 고르면 **씬에서 선택**으로 해당 오브젝트를 Hierarchy에서 바로 찾을 수 있습니다.
- 빌드 뒤에 없어진 오브젝트(Avatar Optimizer가 지운 것 등)는 점검하지 않습니다.

## 텍스처 탭

- 업로드되는 텍스처를 그래픽 메모리(VRAM) 추정 크기 순으로 보여 줍니다. TexTransTool처럼 빌드 중에 텍스처를 만드는 도구의 결과도 들어갑니다.
- 텍스처를 고르면 쓰는 곳을 **오브젝트 › 머티리얼 › 칸**으로 보여 줍니다. lilToon의 칸은 한국어 이름(메인 컬러 2nd, 그림자 마스크, 매트캡 등)으로 나오고, 다른 셰이더는 셰이더에 적힌 이름이 나옵니다.
- 표시:
  - **꺼진 칸**: lilToon에서 그 기능을 껐는데 텍스처가 남은 칸 (예: 아웃라인을 껐는데 윤곽선 굵기 마스크가 남음)
  - **셰이더에 없는 칸**: 셰이더를 바꾸기 전의 칸에 남은 텍스처. 머티리얼에 남아 함께 업로드됩니다.
  - **애니메이션**: 애니메이션이 바꿔 넣는 머티리얼에만 있는 텍스처
  - **안 보임**: 꺼진 칸이나 셰이더에 없는 칸에만 있어서 보이지 않는데 업로드되는 텍스처
- 위쪽 버튼으로 꺼진 칸, 애니메이션 전용, 셰이더에 없는 칸만 모아 볼 수 있습니다.

## 파라미터 탭

### 동기화 비트

빌드된 아바타의 동기화 파라미터를 어디서 왔는지별로 묶어 보여 줍니다(256비트 중 얼마를 쓰는지).
- 프리팹은 그 안의 Modular Avatar Parameters로 찾습니다.
- 아바타의 Expression Parameters에 원래 있던 것은 ‘아바타 기본 파라미터’로 묶입니다.
- 빌드 중에 이름이 바뀐 파라미터(MA의 내부 파라미터 등)는 ‘빌드 중에 생긴 파라미터’로 묶입니다.

### 안 쓰는 파라미터 정리

**켜는 방법**: 정리는 아바타마다 직접 켭니다. 아바타 루트에 **Assembly Checker** 컴포넌트를 붙이고(Add Component › NXYUI › Assembly Checker,
또는 파라미터 탭의 ‘이 아바타에서 정리하기’), 컴포넌트 이름 옆 체크가 켜져 있을 때만 정리합니다. 컴포넌트가 없거나 체크를 끄면 빌드할 때
아무것도 하지 않습니다. 패키지를 설치하는 것만으로는 아무 아바타도 바뀌지 않습니다.

켜 두면 빌드할 때마다(업로드, Play 모드) 다음 어디에도 없는 Expression Parameter를 지웁니다. 이 창의 ‘점검하기’는 꺼져 있어도
무엇을 지우게 될지 보여 줍니다.
- 애니메이터의 전이 조건, 블렌드 트리, 상태 속도·시간 파라미터, Parameter Driver 같은 State Behaviour, 애니메이터 파라미터를 움직이는 애니메이션
- Expressions 메뉴의 컨트롤
- Contact Receiver, PhysBone, VRC Raycast의 파라미터 칸(PhysBone·Raycast가 붙이는 `_IsGrabbed`, `_Hit` 같은 이름 포함)

다른 도구가 빌드를 모두 끝낸 뒤(Modular Avatar, Avatar Optimizer, TexTransTool 다음)에 돌기 때문에, 빌드 중에 추가된 파라미터까지 보고 판단합니다. 씬의 아바타와 Expression Parameters 에셋은 바뀌지 않고, 빌드 결과에만 적용됩니다.

**지우지 않는 것**
- OSC·페이스 트래킹용 이름: `FT/`, `v2/`, `OSC`, `VRCOSC`, `VRCFT`로 시작하는 이름은 아바타 안에서 쓰지 않아도 남깁니다.
- 다른 컴포넌트가 이름(문자열)으로만 가리키는 파라미터: 남기고, 어느 컴포넌트인지 알려 줍니다. VRCFury처럼 NDMF 뒤에 도는 도구가 쓸 수 있기 때문입니다.
- VRChat 기본 파라미터 이름
- Modular Avatar **Sync Parameter Sequence**가 있는 아바타의 동기화 파라미터: PC와 Quest의 동기화 순서를 맞추려고 다른 플랫폼의 파라미터를 넣어 두기 때문입니다.
- 예외 목록에 넣은 이름. 끝에 `*`를 붙이면 그 이름으로 시작하는 것을 모두 남깁니다. 점검 결과의 **남기기** 버튼으로도 넣을 수 있습니다.

**끄기**: 컴포넌트의 체크를 끄거나 파라미터 탭의 ‘이 아바타에서 정리하기’를 끄면 그 아바타에서는 지우지 않습니다. 예외 목록은 그대로 남습니다.

**보고서**: 무엇을 왜 지웠는지는 NDMF 콘솔과 파라미터 탭의 ‘마지막 빌드’에 플랫폼(PC, Android, iOS)별로 나옵니다(에디터를 다시 켜면 ‘마지막 빌드’ 기록은 지워집니다).

**PC와 Quest를 둘 다 올릴 때**: 두 버전의 동기화 파라미터 목록이 같아야 서로 동기화됩니다. 한 플랫폼에서만 쓰는 컴포넌트가 있으면 지우는 파라미터가 달라질 수 있어요. ‘마지막 빌드’에 두 플랫폼 기록이 있고 지운 동기화 파라미터가 다르면 경고가 나오니, 한쪽에만 지워진 이름을 예외 목록에 넣고 다시 올려 주세요.

설정은 아바타 루트의 **Assembly Checker** 컴포넌트에 저장됩니다. 창에서 예외를 넣으면 꺼진 채로 붙고(정리가 저절로 켜지지 않습니다), 실행 취소(Ctrl+Z) 한 번으로 되돌릴 수 있습니다. 이 컴포넌트는 업로드에 들어가지 않습니다.
0.1.0에서는 컴포넌트가 없어도 정리했습니다. 0.2.0부터는 켠 아바타에서만 정리합니다.

## 알아 둘 것

- 점검은 NDMF 빌드만 봅니다. VRCFury는 NDMF 밖에서 돌기 때문에, VRCFury의 Armature Link로 연결한 의상이나 VRCFury 토글로 켜는 오브젝트는 문제처럼 보일 수 있습니다. 그런 항목에는 안내가 붙습니다.
- 바디는 이름이 `Body`인 SkinnedMeshRenderer, 없으면 블렌드쉐이프가 가장 많은 것으로 정합니다.
- 텍스처 크기는 PC용 그래픽 메모리 추정치입니다. 실제 업로드 용량(압축 파일 크기)과는 다릅니다.
