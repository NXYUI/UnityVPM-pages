# Avatar Customizer

[← NXYUI Avatar Tools](../../README.md)

VRChat 아바타의 Expressions 메뉴를 **빌드할 때** 정리하는 Unity 에디터 도구입니다.
메뉴 항목의 이름과 위치를 바꾸거나 숨기고(원본 메뉴 정리), 그 위에 자주 쓰는 항목을 모은 즐겨찾기 메뉴를 만들고,
토글·래디얼의 시작 값과 블렌드쉐이프 조절 컨트롤을 추가합니다. **빌드 결과** 탭에서는 완성될 메뉴를 보면서 바로 편집할 수 있습니다.

아바타의 메뉴·파라미터 에셋은 바꾸지 않습니다. 모든 변경은 빌드할 때 아바타의 빌드용 사본에만 들어갑니다.
Modular Avatar, One-Click Inventory 같은 다른 도구가 빌드 중에 만드는 메뉴도, 완성된 뒤에 다루기 때문에 그대로 정리할 수 있습니다.

## 요구 사항

- Unity 2022.3, VRChat SDK - Avatars
- Modular Avatar, NDMF (VCC·ALCOM이 함께 설치합니다)

## 시작하기

1. Hierarchy에서 아바타를 선택하고 상단 메뉴 **NXYUI › Avatar Customizer**를 엽니다.
2. **빌드 메뉴 읽기**를 눌러 아바타에서 실제로 만들어지는 메뉴를 읽습니다.
   - ‘빠른 읽기’(기본 켜짐)는 Modular Avatar가 메뉴를 설치하는 단계까지만 빌드해 더 빨리 읽습니다. 끄면 NDMF의 모든 단계를 실행하는 전체 빌드로 읽습니다.
   - ‘비교’는 두 방식을 모두 실행해 결과가 같은지 확인합니다. 다르면 이후 전체 빌드로 읽습니다.
   - 두 방식 모두 NDMF만 실행합니다. VRCFury처럼 NDMF 밖에서 실행되는 도구가 넣는 메뉴는 읽지 못합니다([VRCFury와 함께 쓰기](#vrcfury와-함께-쓰기)).
3. **빌드 결과** 탭에서 완성될 메뉴를 보며 바로 편집하거나, **원본 메뉴 정리**(1차)·**즐겨찾기 편집**(2차) 탭에서 규칙을 직접 다룹니다.
4. 씬을 저장한 뒤 Build & Test로 확인합니다. 따로 누를 적용 버튼은 없습니다.

설정은 아바타 루트의 Avatar Customizer 컴포넌트에 저장됩니다(씬에 저장).

## 빌드 결과: 완성될 메뉴에서 바로 편집

마지막으로 읽은 메뉴와 지금 설정으로 빌드와 같은 계산을 다시 해서 완성될 메뉴를 보여 줍니다.
이 도구의 설정을 바꾸면 다시 읽지 않아도 바로 반영됩니다. 아바타의 메뉴·파라미터 에셋이나 다른 도구의 설정을 바꿨을 때는 ‘빌드 메뉴 읽기’를 다시 누르세요.

- 한 메뉴의 여러 페이지는 이어서 보이고, 자동 More 버튼은 `2페이지 · ‘More’ 안 · 5/8칸` 같은 구분선으로 보입니다.
  자동 페이지 버튼으로 보는 것은 도구가 만든 것뿐입니다([알아 두기](#알아-두기)의 ‘자동 페이지 버튼’).
- 줄마다 어디서 온 항목인지(바로가기·즐겨찾기·새 폴더·쉐이프)와 눈여겨볼 점(공유·빌드 제외·옮김·이름 변경)이 붙습니다.
- 항목을 누르면 오른쪽 **선택한 항목**에 어디서 왔는지, 들어온 경로, 바꾸면 어떤 설정이 바뀌는지, 기본값이 나옵니다.
  여러 곳에서 열리는 하위 메뉴(예: 원본과 그 즐겨찾기 바로가기)는 하나의 메뉴라서, 안에서 바꾸면 모든 곳에 적용됩니다.
- **검토** 탭은 지금 설정으로 계산한 경고·안내와 ‘연결 확인’, **숨긴 항목** 탭은 숨긴 항목과 ‘다시 보이기’입니다.
- 다시 읽기가 실패하거나 메뉴를 가져오지 못하면, 탭에는 그 전에 읽은 결과가 남고 ‘이전 결과’라고 표시됩니다. 이때는 다시 읽기에 성공할 때까지 편집할 수 없습니다.

### 편집하기

편집은 앞 단계(1차·2차)의 가장 단순한 규칙으로 저장되고, 편집 한 번은 실행 취소(Ctrl+Z) 한 번으로 되돌립니다.

| 하고 싶은 일 | 방법 | 저장되는 설정 |
| --- | --- | --- |
| 이름 바꾸기 | 오른쪽 이름 칸(F2)에 입력하고 Enter | 원본: 새 표시 이름 / 즐겨찾기 항목: 별칭·메뉴 이름 |
| 순서·위치 바꾸기 | 줄을 끌어 다른 줄의 위·아래에 놓기. 하위 메뉴 줄 가운데에 놓으면 그 안으로, 목록 아래 빈칸은 맨 끝. 다른 메뉴로는 ‘이동…’ | 원본: 옮길 위치(자리까지) / 즐겨찾기 항목: 순서와 폴더 |
| 원본을 즐겨찾기로 옮기기 | 원본을 즐겨찾기 메뉴 안으로 끌어 놓기 | 바로가기 + 원본 숨기기(한 묶음) |
| 원본은 두고 즐겨찾기에 추가 | 오른쪽 클릭 › ‘즐겨찾기에 추가…’. 아직 만들어진 즐겨찾기 메뉴가 없으면 비어 있는 첫 즐겨찾기 메뉴를 만들며 바로 넣을 수 있습니다 | 바로가기 |
| 빼기 | Delete, ‘숨기기’ 또는 ‘삭제’ | 원본: 숨기기 / 즐겨찾기 항목: 그 항목만 삭제 / 즐겨찾기 메뉴 버튼: 확인 뒤 메뉴와 그 안의 설정 삭제(첫 번째 메뉴는 지울 수 없어 버튼 이름이 ‘항목 비우기’이고 항목만 비움) |
| 폴더 만들기 | ‘+ 새 폴더’ 또는 오른쪽 클릭 › ‘이 앞에 새 폴더’ | 아바타 메뉴에는 새 폴더, 즐겨찾기 안에는 즐겨찾기 폴더 |
| 폴더 없애기 | ‘폴더 풀기’ | 폴더만 없애고 안의 항목은 폴더가 있던 자리로 |
| 되돌리기 | ‘원래대로’ | 원본: 이름 변경과 이동을 지움 / 즐겨찾기로 옮긴 원본의 바로가기: 바로가기를 빼고 원본을 옮기기 전 자리에 다시 보이게 함 |

- 원래 자리로 다시 옮기거나 원래 이름으로 돌리면 그 규칙은 지워집니다. 원래 자리는 원래 이웃 중 지금 그 메뉴에 보이는 항목을 기준으로 합니다.
- 즐겨찾기 메뉴 버튼은 늘 그 메뉴의 다른 항목 뒤에 오므로, 맨 끝(목록 아래 빈칸)에 놓은 항목은 그 메뉴의 즐겨찾기 버튼 앞에 들어갑니다.
- 즐겨찾기로 옮긴 원본의 바로가기를 즐겨찾기 밖(아바타 메뉴)으로 끌어 놓으면 바로가기와 숨기기가 함께 풀리고 원본이 그 자리로 갑니다.
  이 바로가기를 ‘삭제’하면 바로가기만 빠지고 원본은 숨긴 채로 남습니다(‘숨긴 항목’에서 다시 보이게 할 수 있습니다).
  원본이 숨긴 메뉴 안에 있으면 짝을 풀어도 보이지 않습니다.
- 블렌드쉐이프 항목을 빼도 컨트롤은 블렌드쉐이프 탭에 남아 있어 다시 넣을 수 있습니다. 마지막 블렌드쉐이프 항목을 빼면 초기화 버튼도 함께 빠집니다.
- 폴더를 풀 때 그 안에 설치했던 즐겨찾기 메뉴는 폴더 자리가 아니라, 폴더가 있던 메뉴의 첫 페이지 앞쪽(고정한 경우)이나 맨 끝에 다시 설치됩니다.
- 키보드: ↑↓ 선택, Enter·→ 열기, Backspace·← 위로, F2 이름 바꾸기, Delete 빼기. 목록의 줄을 누른 뒤에만 동작하고(그때 선택한 줄이 파란색, 아니면 회색), 창의 다른 곳을 누르거나 이름 칸에 입력 중일 때는 동작하지 않습니다. ↑↓로 고른 줄은 목록이 따라 스크롤됩니다.
- ‘이동…’에서 고를 수 없는 메뉴에는 이유(지금 있는 곳, 자기 안으로 옮기기 등)가 함께 적힙니다.

### 아이콘

**선택한 항목** 탭의 ‘아이콘’ 칸에서 아이콘을 고르거나 바꿉니다.

- 텍스처를 끌어 놓거나 골라서 바꿉니다. 원본 항목은 비우면 아이콘 없이 보이고, 즐겨찾기 항목은 비우면 원본 아이콘을 따라갑니다.
- **아이콘 만들기…**: 아바타의 오브젝트를 찍어 아이콘을 만듭니다. 오른쪽에 미리보기와 찍을 오브젝트 목록, 각도(정면·3/4·옆·위), 확대, ‘아바타와 함께’가 나옵니다.
  - 토글이면 그 토글이 켜는 오브젝트를 미리 골라 둡니다. 마지막으로 읽은 빌드의 FX 레이어에서 확실히 알 수 있을 때만 고르고, 모르면 직접 고르게 합니다.
  - 꺼져 있는 오브젝트도 아이콘에서는 켜서 찍습니다. 씬의 아바타는 바뀌지 않습니다.
  - ‘만들어서 적용’을 누르면 256×256 PNG를 `Assets/NXYUI/Avatar Customizer/Icons/<아바타 이름>/`에 새 파일로 저장하고(VRChat이 받는 크기와 압축), 그 항목의 아이콘으로 정합니다.
    실행 취소는 아이콘 지정만 되돌리고 파일은 남습니다.
- **원본 아이콘으로**: 원본 항목의 아이콘 규칙을 지웁니다.
- 원본 항목의 아이콘은 그 항목이 보이는 모든 곳(아이콘을 따로 정하지 않은 즐겨찾기 바로가기 포함)에 반영됩니다.

### 놓을 수 없는 자리

놓을 수 없는 자리에 끌면 거부 표시와 함께 목록 아래에 이유가 나옵니다.

- 즐겨찾기 메뉴 버튼은 첫 페이지 맨 앞(고정)이나 맨 끝에만 놓을 수 있습니다. 같은 자리의 즐겨찾기 메뉴끼리의 순서(고정한 것끼리, 맨 끝의 것끼리)는
  즐겨찾기 편집 탭의 메뉴 순서를 따르고, 빌드 결과에서는 바꿀 수 없습니다.
- 바로가기·즐겨찾기 폴더·블렌드쉐이프 항목은 즐겨찾기 안에서만 옮길 수 있습니다. 즐겨찾기로 옮긴 원본의 바로가기만 즐겨찾기 밖으로 옮길 수 있습니다.
- 새 폴더는 즐겨찾기 안으로 옮길 수 없고, 메뉴와 폴더는 자기 안으로 옮길 수 없습니다.
- 편집하면 다른 즐겨찾기 메뉴나 바로가기가 빌드에서 빠지게 될 때(같은 자리에 같은 이름, 순환, 경로와 동작이 같은 항목)는 바꾸지 않고 이유를 알려 줍니다.

### 빈 폴더

새로 만든 폴더는 빈 채로는 빌드에서 빠집니다. 빌드 결과에는 흐리게 ‘빌드 제외’로 남아 있어 항목을 넣을 수 있고, 검토 탭에 경고가 나옵니다.
빈 즐겨찾기 폴더와, 항목은 있지만 빌드할 수 있는 것이 없는 즐겨찾기 메뉴도 흐리게 남고 검토 탭에 안내가 나옵니다.
항목이 하나도 없는 즐겨찾기 메뉴는 빌드 결과에 보이지 않고(즐겨찾기 편집 탭에서 채웁니다), 설치 위치를 찾지 못했거나
같은 자리에 같은 이름의 메뉴가 있는 즐겨찾기 메뉴는 흐린 버튼 없이 그 경고만 나옵니다.

## 1차: 원본 메뉴 정리

아바타의 메뉴 **원본 자체**를 고칩니다. 즐겨찾기보다 먼저 적용됩니다.
왼쪽 목록은 아바타의 도구들이 만든 그대로의 메뉴입니다.

- **새 표시 이름**: 항목의 이름을 바꿉니다. 그 항목이 보이는 모든 곳(별칭이 없는 즐겨찾기 바로가기 포함)에 반영됩니다.
- **옮길 위치**: 항목을 다른 곳으로 옮깁니다. 원래 자리에서는 사라집니다.
  - 최상위
  - 새 최상위 폴더: 이름을 정하면 그 이름의 최상위 하위 메뉴 안으로 넣습니다. 없으면 빌드 때 만듭니다. 같은 이름을 고른 항목은 한 폴더에 모입니다.
  - 빌드 메뉴의 하위 메뉴(예: 직접 만든 ‘옷장’ 폴더)
- 이 탭에서 옮긴 항목은 대상 메뉴의 끝에 붙습니다. 자리를 정하거나 빌드 결과에서 만든 새 폴더로 옮기려면 빌드 결과에서 끌어 놓으세요.
- 하위 메뉴는 안의 항목과 함께 옮겨집니다. 옮긴 뒤 빈자리는 다음 페이지 항목으로 채웁니다.
- **메뉴에서 숨기기**: 항목을 빌드한 메뉴에서 뺍니다. 하위 메뉴는 안의 항목과 함께 빠지고, 빈자리는 다음 페이지 항목으로 채웁니다.
  - 기능(파라미터, 애니메이터)은 그대로 남고, 메뉴로 값을 바꿀 수 없게 될 뿐입니다. 저장되는(Saved) 값은 숨기기 전 마지막 값이 유지됩니다.
  - 숨긴 항목도 즐겨찾기에 넣을 수 있습니다. 원본은 숨기고 즐겨찾기에서만 쓸 수 있습니다.
  - 이동이 먼저 적용되므로, 숨긴 하위 메뉴에서 다른 곳으로 옮긴 항목은 계속 보입니다.
- ‘More 이름’에는 자동 페이지 버튼에 쓸 이름(예: 더 보기)을 넣을 수 있습니다. Modular Avatar의 ‘More’와, 업로드할 때 VRCFury가 만든 ‘Next’에 함께 적용됩니다.

## 2차: 즐겨찾기 편집

1차로 정리된 메뉴를 바탕으로, 원본은 그대로 둔 채 **바로가기를 모은 메뉴**를 만듭니다.

- 왼쪽 목록은 원본 메뉴 정리가 반영된 메뉴입니다. 정리 규칙을 바꾸면 다시 읽지 않아도 바로 바뀝니다.
- 위쪽 **미리보기**를 누르면 정리된 메뉴를 페이지 단위로 확인할 수 있고, 옮긴 항목에는 ‘옮김’이 붙습니다. 숨긴 항목은 목록에 ‘숨김’으로 남고 미리보기에서는 빠집니다.
- ‘+ 메뉴’로 즐겨찾기 메뉴를 여러 개 만들 수 있습니다. 메뉴마다 이름, 아이콘, 설치 위치(최상위 또는 왼쪽 목록의 ‘위치’로 고른 하위 메뉴), 첫 페이지 고정을 정합니다.
  빌드 결과에서 즐겨찾기 메뉴 버튼을 새 폴더 가운데에 놓으면 그 폴더에 설치할 수도 있습니다.
- ‘메뉴 삭제’는 확인한 뒤 그 메뉴와 안의 설정을 지웁니다. 첫 번째 메뉴는 지울 수 없어서 버튼이 ‘항목 비우기’로 바뀌고, 항목만 모두 비우며 이름·아이콘·설치 위치는 남깁니다(빌드 결과에서도 같습니다). 이 버튼은 ‘+ 메뉴’·‘가져오기’와 떨어져 있습니다.
- 바로가기는 원본과 같은 파라미터를 써서 어느 쪽에서 켜도 같이 움직입니다. 폴더, 순서, 별칭, 아이콘을 자유롭게 정할 수 있습니다.
- 기본값: 토글은 꺼짐/켜짐, 래디얼은 0–100%로 아바타를 처음 불러올 때의 값을 정합니다. 하위 메뉴 바로가기는 ‘안의 항목’을 펼쳐 안쪽 항목의 기본값도 정할 수 있습니다.

### 두 기능의 차이

| | 원본 메뉴 정리 (1차) | 즐겨찾기 편집 (2차) |
| --- | --- | --- |
| 하는 일 | 원본 항목의 이름과 위치를 바꾸거나 숨김 | 바로가기를 모은 새 메뉴를 만듦 |
| 원본 | 바뀜(옮기거나 숨기면 원래 자리에서 사라짐) | 원래 자리에 그대로 남음 |
| 꾸미기 | 이름, 위치(빌드 결과에서는 자리까지), 새 폴더 | 폴더·순서·별칭·아이콘·첫 페이지 고정 |
| 쓰기 좋은 경우 | 최상위 정리, 다른 도구가 만든 메뉴를 원하는 폴더로 | 자주 쓰는 항목만 모은 내 메뉴 |

자주 쓰는 항목은 즐겨찾기에 두고, 원본은 ‘옷장’ 같은 보관 폴더로 옮기거나 숨기면 최상위를 깔끔하게 유지할 수 있습니다.
빌드 결과에서 원본을 즐겨찾기로 끌어 놓으면 이 두 가지(바로가기 + 원본 숨기기)를 한 번에 합니다.

## 블렌드쉐이프

- ‘블렌드쉐이프’ 탭에서 Skinned Mesh Renderer의 블렌드쉐이프를 찾아 값을 바로 바꿀 수 있습니다(실행 취소 가능).
- ‘+ 래디얼’ / ‘+ 토글’로 게임 안에서 그 블렌드쉐이프를 조절하는 컨트롤을 만들면, 편집 중인 즐겨찾기 메뉴에 들어갑니다.
  블렌드쉐이프 컨트롤은 원래 메뉴에 없는 새 항목이라 즐겨찾기 메뉴에만 넣을 수 있습니다.
- 첫 컨트롤을 만들면 ‘블렌드쉐이프 초기화’ 버튼이 함께 들어갑니다. 누르면 모든 블렌드쉐이프 컨트롤이 정한 기본값으로 돌아갑니다.
- **한 블렌드쉐이프에는 컨트롤을 하나만 둘 수 있습니다.** 같은 블렌드쉐이프에 래디얼과 토글을 둘 다 두면 두 값이 더해져 어느 쪽도 정한 대로 움직이지 않기 때문입니다.
  이미 컨트롤이 있는 블렌드쉐이프에서는 ‘+ 래디얼’·‘+ 토글’이 꺼지고(종류는 아래 목록에서 바꿉니다), 예전 설정에 둘이 남아 있으면 즐겨찾기에서 먼저 나오는 하나만 빌드하고 나머지는 이유와 함께 빌드에서 뺍니다.
  이때 설정만 보고도 메뉴에 들어갈 수 없는 쪽(설치할 새 폴더가 없는 메뉴, 설치 위치가 정해지지 않은 메뉴, 지워진 폴더 안의 항목)은 건너뛰고 다음 컨트롤을 빌드합니다.
  설치 위치를 찾지 못한 것은 완성된 메뉴에서만 알 수 있어서, 먼저 나온 컨트롤이 그렇게 빠지면 뒤의 컨트롤도 함께 빠지고 검토 탭과 Console에 그렇게 알려 줍니다.
- 설정만으로 메뉴에 들어갈 수 없는 컨트롤(위와 같은 경우)은 아예 빌드하지 않아 파라미터도 동기화 메모리도 쓰지 않습니다.
  설치 위치를 찾지 못했거나, 설치한 메뉴를 숨겨서 열 길이 없는 컨트롤은 메뉴에는 없지만 **파라미터는 남아 동기화 메모리를 씁니다**. 검토 탭과 Console에 몇 bit인지 알려 줍니다.
  메뉴는 업로드 빌드의 마지막에 완성되는데, 그때는 Modular Avatar의 Sync Parameter Sequence와 VRCFury의 모바일 정렬이 PC·Quest 파라미터 순서를 이미 맞춰 둔 뒤라서, 그 자리에서 파라미터를 빼면 한쪽 플랫폼에서만 뒤의 동기화 파라미터가 밀리기 때문입니다.
- 컨트롤의 파라미터 이름을 아바타의 Expression Parameters나 MA Parameters, 파라미터를 알리는 다른 도구의 컴포넌트가 다른 타입으로 이미 쓰고 있거나, 아바타 루트의 MA Parameters가 그 이름을 바꾸면,
  Modular Avatar 빌드가 멈추거나 메뉴가 컨트롤을 움직이지 못하므로 그 컨트롤은 빌드에서 빼고 어느 컴포넌트 때문인지 알려 줍니다.
  ‘동기화 N bit’에는 빌드되는 컨트롤만 셉니다.
- 같은 블렌드쉐이프를 움직이는 애니메이션이 이미 있으면 알려 줍니다. 아바타의 FX 레이어나 레이어 우선순위 0 이하의 MA Merge Animator라면 메뉴 값이 우선하고,
  레이어 우선순위가 더 높은 MA Merge Animator라면 그 애니메이션이 재생되는 동안에는 그쪽 값이 보입니다. VRCFury가 넣는 애니메이션(Full Controller)은 확인하지 못합니다.
- 메시 오브젝트를 지운 컨트롤은 빌드에서 빠지고, **빌드 결과** 탭에는 원래 자리에 흐리게 이유와 함께 보입니다.
  블렌드쉐이프 탭 위쪽(또는 빌드 결과에서 그 항목을 골랐을 때)의 **정리**는 그런 컨트롤과 즐겨찾기 항목, 그 때문에 비게 된 즐겨찾기 폴더를 지웁니다(실행 취소 가능).
  EditorOnly 안에 넣어 둔 메시와, 오브젝트는 남아 있고 Mesh 칸만 비어 있는 컨트롤은 지우지 않습니다(다시 넣으면 되살아납니다). 그런 컨트롤은 목록에서 이유를 보고 ‘×’로 지울 수 있습니다.

## One-Click Inventory와 함께 쓰기

One-Click Inventory(OCI)는 빌드 중에 옷장 메뉴를 새로 만들고 자기 컴포넌트를 지웁니다.
Avatar Customizer는 완성된 메뉴를 다루므로 OCI 메뉴도 다른 메뉴처럼 정리할 수 있습니다.

- **OCI 메뉴를 폴더로 옮기기**: ‘빌드 메뉴 읽기’ 뒤 빌드 결과에서 OCI 메뉴(예: CustomCostume)를 원하는 폴더로 끌어 놓거나, 원본 메뉴 정리에서 ‘옮길 위치’를 정합니다.
- **자기 메뉴를 가진 아이템은 메뉴가 최상위에 따로 남습니다.** 예를 들어 의상에 MA Menu Installer와 MA Menu Item(장식 토글 등)이 들어 있으면,
  그 메뉴는 OCI 옷장과 별개로 최상위에 설치됩니다. 에셋은 그대로 두고, 그 메뉴도 원하는 폴더로 옮기세요(추천).
- 에셋을 고쳐서라도 옷장 항목 하나로 합치고 싶다면: 아이템 자체의 MA Menu Installer와 MA Menu Item(하위 메뉴)을 지우고,
  안쪽 메뉴 항목(토글들)에 OCI의 **Inventory Menu Installer**를 붙여 ‘연결된 인벤토리’를 그 아이템으로 지정합니다.
  그러면 옷장 안의 그 아이템이 ‘활성화’ 토글과 장식 토글을 함께 가진 하위 메뉴가 됩니다. 에셋 원래 구성을 바꾸는 방법이라 나중에 되돌리기 번거롭습니다.
- **OCI의 ‘메뉴 통합’은 켜지 않는 것을 추천합니다.** 아이템에 MA Menu Item(하위 메뉴)이 있을 때 켜면 그 메뉴의 항목이 사라지고 아이템 토글이 최상위에 따로 생깁니다(시험 빌드에서 확인).
- OCI 인벤토리 오브젝트에 MA Menu Item과 MA Menu Installer를 따로 붙이면 같은 이름의 메뉴가 하나 더 생깁니다. 정리는 Avatar Customizer에서 하세요.

## VRCFury와 함께 쓰기

VRCFury는 NDMF 플러그인이 아니라서, 업로드할 때 Modular Avatar가 메뉴를 만든 뒤에 **따로** 실행됩니다. 이 창의 ‘빌드 메뉴 읽기’(빠른 읽기·전체 빌드 모두)는 NDMF만 실행하므로 VRCFury가 하는 일은 보지 못합니다.
아바타에 VRCFury 컴포넌트가 있으면 창 위쪽에 이 안내가 나옵니다.

- **VRCFury가 넣는 메뉴 항목(Toggle, Full Controller의 메뉴 등)은 읽은 메뉴에 나오지 않습니다.** 이 창에서 즐겨찾기에 넣거나 옮기거나 숨길 수 없습니다.
  ‘비교’가 두 결과가 같다고 해도, VRCFury 항목까지 포함한 업로드 결과와 같다는 뜻은 아닙니다.
- 업로드할 때 이 도구는 VRCFury가 끝난 뒤의 메뉴에 설정을 적용합니다. 항목은 메뉴 경로와 파라미터로 다시 찾기 때문에, 읽은 메뉴에 있던 항목의 설정은 페이지가 달라져도 이어서 적용됩니다.
  그때 찾지 못한 설정은 빌드에서 빠지고 Console에 `[Avatar Customizer]` 경고로 남습니다.
- VRCFury는 항목을 넣은 뒤 8칸이 넘는 메뉴를 ‘Next’ 버튼으로 다시 나눕니다. 그래서 업로드한 메뉴의 페이지 나눔이 빌드 결과 탭에 보이는 것과 다를 수 있습니다.
  이 도구는 VRCFury의 ‘Next’(Override Menu Settings로 바꾼 이름·아이콘 포함. 아이콘이 256px보다 크거나 압축되지 않아 VRCFury가 줄인 사본으로 바꿔 넣은 경우도)를 자동 페이지 버튼으로 알아보고, 숨기거나 옮긴 자리를 다음 페이지 항목으로 채우며, 고정한 즐겨찾기 메뉴를 첫 페이지 앞에 둡니다.
- VRCFury 항목까지 이 창에서 보고 고르게 하는 기능은 아직 없습니다.

## 알아 두기

- **자동 페이지 버튼**: 8칸이 꽉 찬 메뉴의 마지막 칸에서 나머지를 여는 버튼 중, 도구가 만든 것만 페이지로 이어서 봅니다.
  Modular Avatar의 ‘More’(이름과 MA의 More 아이콘이 모두 맞을 때)와, VRCFury가 있는 아바타의 ‘Next’입니다. 그 버튼이 여는 메뉴를 다른 하위 메뉴도 열고 있으면(같은 메뉴를 두 곳에서 여는 경우) 페이지가 아니라 별도 메뉴로 봅니다.
  - 직접 만든 하위 메뉴는 이름이 ‘More’이고 마지막 칸에 있어도 일반 하위 메뉴입니다. 2.8.2까지는 아이콘 없는 ‘More’도 자동 페이지로 보고, 항목을 숨기거나 옮기면 그 안의 항목을 앞 페이지로 끌어올렸습니다.
    그런 메뉴 안의 항목에 걸어 둔 예전 설정은 ‘경로 이동’으로 이어서 적용됩니다. 앞 페이지에 이름이 같은 다른 항목이 있어도 그 항목이 아니라 메뉴 안의 항목을 찾습니다.
- 같은 하위 메뉴를 여러 곳에서 여는 메뉴는 그대로 지원합니다(‘공유’). 같은 하위 메뉴를 겹겹이 여러 길로 여는 메뉴는 목록이 2만 줄을 넘으면 이미 나온 메뉴를 다른 길로 다시 적지 않고, 검토 탭에 알려 줍니다. 빌드되는 메뉴는 그대로이고, 이미 저장한 설정이 가리키는 항목은 그 길에서도 그대로 찾습니다.
- 이름과 경로가 바뀌어도 항목은 메뉴 경로와 파라미터로 다시 찾습니다. 찾지 못하면 ‘⚠ 연결 필요’로 표시되고, ‘다시 연결’이나 빌드 결과의 ‘연결 확인’으로 고칠 수 있습니다.
- 빌드 결과에서 항목을 옮기면 그 항목을 가리키던 즐겨찾기 바로가기, 설치 위치, 기본값도 새 경로로 함께 이어집니다.
- 2.6 이하의 ‘새 최상위 폴더’로 생긴 폴더는 빌드 결과에서 편집하면 같은 자리·같은 내용의 새 폴더로 바뀝니다. 그 폴더를 여는 즐겨찾기 바로가기가 있으면 편집할 수 없습니다.
- 2.7 이하로 되돌리면 원본 항목에 정한 아이콘은 적용되지 않습니다(즐겨찾기 항목과 폴더의 아이콘은 그대로).
- **2.6으로 되돌릴 때**: 빌드 결과에서 편집한 설정은 일부만 적용됩니다.
  - 새 폴더는 사라집니다. 새 폴더로 옮긴 항목은 최상위 끝으로 가고, 원래 최상위에 있던 항목은 원래 자리에 남습니다.
  - 같은 메뉴 안에서 순서만 바꾼 항목은 원래 자리로 돌아가고, 다른 메뉴로 옮긴 항목은 그 메뉴의 끝에 붙습니다.
  - 새 폴더에 설치한 즐겨찾기 메뉴는 예전에 고른 설치 위치를 따르거나 설치되지 않습니다. 설치되지 않으면 그 메뉴로 옮긴 원본은
    바로가기 없이 숨기기만 남아 메뉴에서 사라집니다.
  - 즐겨찾기로 옮긴 원본은 바로가기와 숨기기가 따로 남아 결과가 같습니다.
  - 더 이전 버전은 숨기기(2.6부터)와 이동(2.4부터)을 읽지 못해 그만큼 더 달라집니다.
- 빠른 읽기와 전체 빌드는 생성 에셋을 Assets 아래 임시 폴더에 두었다가 읽기가 끝나면 지웁니다.
- 저장되는(Saved) 파라미터의 기본값은 사용자가 이미 바꾼 값이 있으면 그 값이 유지됩니다.
- 열린 씬의 다른 아바타에서 설정을 ‘가져오기’로 복사할 수 있습니다. 이 아바타의 설정을 모두 바꾸므로, 설정이 하나라도 있으면(기본값·아이콘·블렌드쉐이프 컨트롤만 있어도) 바꾸기 전에 확인합니다.
- Avatar Menu Favorites에서 옮길 때: Avatar Customizer를 설치하면 Avatar Menu Favorites는 자동으로 제거되고, 씬의 설정 컴포넌트는 그대로 이어집니다.
